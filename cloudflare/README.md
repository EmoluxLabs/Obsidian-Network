# Cloudflare layer — gateway and hosting only

> **The chain does not depend on any of this.** Delete this directory, delete the
> Cloudflare account, block the DNS records: Obsidian Core nodes keep producing
> blocks, validating transactions and serving the same data on their RPC ports.
> Nothing here holds a key, signs anything, prices anything or decides anything.

## What this directory is for

| Purpose | File |
| --- | --- |
| Serve the interface at an edge, with strict security headers and honest caching | `src/worker.js` (deployed by `wrangler.toml`) |
| Cache rules, WAF, rate limits, TLS and DNS as code, with reasons | `cloudflare-config.md` |
| Optional Terraform for operators who want the zone configured reproducibly | `terraform/main.tf` |
| Tests that prove the worker is a cache and a proxy — never an authority | `test/worker.test.mjs` |

## The one rule

The worker's job is: **forward, cache, and stay out of the way**.

* It may serve a cached copy of a *static* asset or of `/api/rpc` **only** with a
  short TTL, and it must always pass through the `x-obsidian-node` header so the
  browser can see which node produced the answer.
* It must never serve a cached response for `POST /api/rpc`, which is how signed
  transactions travel.
* It must never invent a response when the origin is unreachable — a stale cache
  is acceptable for an hour-old block list, never acceptable for a transaction
  submission or an account check.

```bash
cd cloudflare
npx wrangler deploy            # publishes the worker
node --test test/worker.test.mjs   # proves the worker is still just a proxy
```

## Deploying the sites

The product sites (`landing/`, `mine/`, `wallet/`, `explorer/`, `social/`,
`capsule/`, `ons/`, `circle/`, `developer/`, `app/`, `audit/`) are plain static
directories generated by `npm --prefix obsidian-interface run build:sites`. They
can be published by Cloudflare Pages, any object store, nginx, or a laptop:

```bash
npx wrangler pages deploy landing --project-name obsidian-landing
npx wrangler pages deploy mine    --project-name obsidian-mine
```

Whichever host you choose, the pages call **one** backend: `/api/*` and
`/api/rpc` on the interface. Point that at nodes you run. A CDN that can read a
chain is a convenience; a CDN that is the only reader is a single point of
control.

## Threat model in one paragraph

Cloudflare (or any CDN) can lie to **a browser that chose to trust it**. It
cannot make a node accept a transaction it would otherwise reject, cannot change
the max supply, cannot mint, cannot move OBS, and cannot change the genesis id.
That is the whole point of the architecture: the browser's trust in a proxy is
optional, because signatures are verified by nodes and the chain is verified by
whoever holds it. Run your own node, and none of the above matters.
