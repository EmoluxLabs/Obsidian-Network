# Obsidian Network

**A Proof of Time (PoT) blockchain with a hard cap of 21,000,000 OBS, and the products
built directly on its state.** Mining, payments and `.obs` names are chain state —
not rows in a company database.

```
consensus → node state → verified chain data → APIs and indexes → frontend cache
```

The arrow never points backwards. Cloudflare is a cache. This website is a cache.
Your browser is a cache. None of them can create OBS, move OBS, price a name, or
decide a claim.

---

## The three things you can actually do

| | |
| --- | --- |
| **Start mining** → [`/mine/`](mine/index.html) | One signed claim every four hours, six per day, 0.001 OBS/day at launch. No account, no KYC, no device clock. |
| **Create a wallet** → [`/wallet/`](wallet/index.html) | Generated in your browser from 256 bits of CSPRNG entropy, encrypted with your passphrase, never transmitted. |
| **Explorer** → [`/explorer/`](explorer/index.html) | Blocks, transactions and names from real nodes — and never a wallet balance. |

## Launch it

**On an Android phone, start with [docs/TERMUX-QUICKSTART.md](docs/TERMUX-QUICKSTART.md)**: only the commands
to paste, one section per network, and a `doctor` command for when something does not work.

**[docs/LAUNCH-GUIDE.md](docs/LAUNCH-GUIDE.md)** is the one document to follow for everything else: Termux on Android
step by step, then **devnet, testnet, staging and mainnet each in a section of their own** with
their own commands and ports, then the interface, then hosting. For a server see
**[docs/ORACLE-VPS-DEPLOYMENT.md](docs/ORACLE-VPS-DEPLOYMENT.md)** (Oracle Cloud, free tier and paid).

The short version, from the built release archives (see the guide for the Termux install):

```bash
cd ~/obsidian/run
bash obsidian-network.sh devnet start      # a node and its interface; http://127.0.0.1:38788
bash obsidian-network.sh devnet status
bash obsidian-network.sh devnet doctor     # what is wrong, if anything, and the command that fixes it
bash obsidian-network.sh devnet stop
```

| Network | Chain id | Prefix | Node RPC / P2P | Interface |
| --- | --- | --- | --- | --- |
| mainnet | 7777 | `obs1` | 8630 / 8631 | 8788 |
| testnet | 7778 | `tobs1` | 18630 / 18631 | 18788 |
| staging | 7779 | `sobs1` | 28630 / 28631 | 28788 |
| devnet | 7780 | `dobs1` | 38630 / 38631 | 38788 |

There is **no default network** anywhere: every command that depends on one has to be told. Networks
are isolated by genesis document, id, hash and chain id; a data directory written by another network
is refused rather than mixed, a peer from another network is refused on connection, and an
interface refuses a node that follows another network.

## Run it from source

```bash
# 1. a node on the disposable devnet
cd obsidian-core
npm ci && npm run build
OBSIDIAN_KEYSTORE_PASSPHRASE='devnet-passphrase' npm run start:devnet      # RPC 38630, P2P 38631

# 2. the interface, reading that node (second terminal)
cd ../obsidian-interface
npm ci && npm run build
node dist/server/main.js --network devnet                                  # http://127.0.0.1:38788

# 3. open http://127.0.0.1:38788 — create a wallet, claim, send a payment
```

(`npm start` on its own refuses to run: name the network, as `npm run start:devnet`,
`start:testnet`, `start:staging` or `start:mainnet` do.) Or with Docker (verify the recipe first):

```bash
cd obsidian-core/deployment/docker
OBSIDIAN_NETWORK=devnet OBSIDIAN_KEYSTORE_PASSPHRASE='a-long-passphrase' docker compose up -d
./verify.sh
```

## Run a node

```bash
node dist/index.js start --network devnet             # name the network: there is no default
node dist/index.js start --network devnet --no-mine   # follow and validate only
node dist/index.js health --network devnet            # what the node sees
node dist/index.js validate --network devnet          # verify the chain on disk (stop the node first)
node dist/index.js genesis init --network devnet      # the genesis document, id and hash
node dist/index.js wallet new --network devnet        # a wallet, offline, no server involved
node dist/index.js audit                              # the design audit (no network needed)
```

## Verify everything

```bash
cd obsidian-core         && npm ci && npm run build && npm test     # consensus, storage, p2p, rpc, security
cd ../obsidian-interface && npm ci && npm run build && npm test     # accounts, wallet, pages, a live-node UI suite
cd ..
node --test cloudflare/test/worker.test.mjs                         # the edge
node --test tests/scripts/*.test.mjs                                # signing, soak verdict, invitation, helper, repo consistency
node --test tests/e2e/cluster.test.mjs                              # three real nodes
node --test tests/e2e/networks.test.mjs                             # four networks side by side, and their isolation
node --test tests/e2e/ecosystem.test.mjs                            # the interface's own code against a real node: ONS and the revenue split
node scripts/check-invariants.mjs                                   # the protocol and economic invariants
./scripts/package-releases.sh                                       # runs all of the above, then builds the archives + SHA256SUMS
cd releases && sha256sum -c SHA256SUMS
../scripts/verify-release.sh obsidian-core-1.6.1.tar.gz --with-tests
```

The suites, the invariant check and the packaging gate fail loudly if anything drifts, including
an economic constant. All of it runs in CI on every push; the counts are in the CI log and in
[`CHANGELOG.md`](CHANGELOG.md) rather than hard-coded here where they would go stale.

Then verify the *chain* you are trusting, not just the code:

```bash
RPC=8630     # your network's node RPC port from the table above (8630 is mainnet)
curl -s localhost:$RPC/audit/compliance | jq   # WAC, signup allocation, KYC: all absent
curl -s localhost:$RPC/params | jq '.maximumSupplyObs, .genesisAllocationObs'
curl -s localhost:$RPC/status | jq '{height, genesisId, paramsHash}'
```

## Consensus: Proof of Time

Obsidian is a **Proof of Time (PoT)** chain. Block production is scheduled by
the validator rotation and gated by protocol time — there is no hash puzzle, no
nonce search and no advantage to computing faster. Hashing and signatures secure
identity and integrity; they are not the competition.

* Fork choice: finalized anchor → fixed one-unit-per-valid-block **PoT Weight** → height → lowest block hash. Equal-height ties resolve by hash, so transaction volume, peer arrival order and header-hash grinding buy no authority.
* Native PoT finality: `floor(2N/3)+1` active-validator signatures finalize sequential checkpoints after a 64-block stable-set bootstrap. It complements PoT and is not a blanket BFT or immutability claim.
* **PoT Difficulty** reports how block spacing tracks the 5-second target. It is
  a published measurement, not an extra acceptance rule — `/pot` says so in the
  payload.
* **Time-Rate** replaces hash rate: verified blocks and transactions per minute
  of protocol time.
* Your device clock decides nothing. A validating node's clock can reject a
  future-dated block; it can never admit a backdated one.

Full details, with the file and route for every claim:
[`docs/proof-of-time.md`](docs/proof-of-time.md).

## Node runners get 90% of ONS revenue

ONS registration and renewal fees are the protocol's only revenue source, and
they are split inside the state transition:

```
ONS revenue ──┬── 90% → Node Runner Reward Pool
              └── 10% → treasury wallet
```

A node earns from uptime, participation, reliability and responsiveness that
**other nodes attested** — there is no field in which a node can report its own
performance. Registration binds a node identity to a reward wallet with
signatures from both, and moves no funds: the protocol has exactly one bond, the
20,000 OBS validator bond, so nobody can be priced out of running a node.
Settlement runs inside a block, so payouts happen with nobody online.
Gas still goes to the Mining Pool and is never counted as revenue.

See [`docs/node-runner-rewards.md`](docs/node-runner-rewards.md) and `/node/`.

## Supply and genesis, precisely

* Hard maximum: **21,000,000 OBS**, enforced on every issuance.
* One-time genesis allocation: **100,000 OBS**, awarded atomically to the **first
  protocol-valid mining claim** — not at registration, not to a founder address.
  That wallet becomes the on-chain **treasury wallet**.
* Registration creates an account with **0 OBS**.
* No admin mint. No WAC. No $5 activation. No mining KYC. No native exchange. No
  legacy 3,000,000 OBS allocation. Each of those is verifiable from a running node
  in `docs/removal-report.md`.
